Security.

How Carbon protects your account, your Spotify sign-in and your updates, and how to tell us about a problem without making it public.

Report a problem privately

Please don’t open a public issue for a security problem. Report it through GitHub’s private vulnerability reporting instead.

Report privately on GitHub

What to include

  • What you found
  • How to reproduce it
  • The version of Carbon you’re on

You’ll get a reply within a few days, and credit in the release notes once it’s fixed, unless you’d rather not.

Supported versions. Only the latest release gets security fixes. Carbon updates itself, so most people are already on it.

How Carbon protects you

What we store and why is in the privacy policy. This is how it’s kept safe.

Your account

Your password stays in your browser

Your browser turns your password into a key with Argon2id. The server stores only an HMAC-SHA-256 of that key, made with a server secret. The password itself never leaves the browser.

New browsers need a code

Signing in on a new browser takes a code we email you. The code is stored hashed. After that, the browser is remembered.

Sessions that scripts can’t read

Session cookies are HttpOnly, Secure, SameSite=Lax and carry the __Host- prefix. Any request that changes something needs a CSRF header and an allowed Origin.

Rate limits

Requests are limited per network and per account. Ten failed sign-ins from one network pause that email on that network for 30 minutes.

Suspended accounts

Admins can suspend accounts that break the terms. Suspension signs the account out everywhere.

The app

Spotify sign-in

Carbon signs in to Spotify with Authorization Code and PKCE, so it never sees your Spotify password. Your token is kept in Windows Credential Manager or the macOS Keychain.

Last.fm, if you turn it on

Carbon’s account service signs Last.fm requests and keeps the signing secret on the server. Your Last.fm connection is stored encrypted in the system credential store, bound to your Carbon account.

Signed updates

Every update is signed. Carbon verifies the signature before it installs and refuses any update that doesn’t match.

The website

A strict website

getcarbon.cc sends a strict Content-Security-Policy and runs no inline scripts.
