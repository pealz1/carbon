# Domain documentation

Use one `GLOSSARY.md` at the repository root and keep architecture decision records in `docs/adr/`.

Read the glossary when it exists and use its terms in issues, discussions, code, and tests. Read the decisions relevant to the change. If a proposal conflicts with a recorded decision, identify the decision and explain what has changed.

Create the glossary when the team settles its first term. Add a numbered Markdown file under `docs/adr/` when the team makes its first architectural decision.
